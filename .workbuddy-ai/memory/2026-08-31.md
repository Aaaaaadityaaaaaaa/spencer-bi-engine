## Verification harness notes (reusable next time)
- Backend does NOT call `load_dotenv`; reads `os.getenv` directly. To enable AI features, must start backend with env loaded. `set -a; source .env; set +a; uvicorn ...` breaks on values with shell-special chars (e.g. `(`, `)`). Use a python wrapper: `backend/run_dev.py` parses .env (skip blanks/comments, strip surrounding quotes) into os.environ, then `subprocess.call([python, "-m", "uvicorn", "main:app", ...])`. Backend start is slower with env loaded (key pool init) — give it ~25-30s before health.
- `vue-tsc` / `vite` bin scripts are bash shims; invoking them via `node node_modules/.bin/<bin>` fails ("missing ) after argument list"). Use the real entrypoint: `node node_modules/vue-tsc/bin/vue-tsc.js` / `node node_modules/vite/bin/vite.js`.
- Vite `build` crashes inside the WorkBuddy `node-safe-delete-shim` on `emptyDir(dist)` (rmSync guard). Workaround for type-checking only: `vue-tsc --noEmit` validates edits without touching dist. For real build, run outside this sandbox or `vite build` in a way that avoids the shim.
- Playwright `text=/^.../` regex anchors to the start of the matched ELEMENT's text, but `page.locator('text=/^X/').count()` against a banner whose text doesn't start with X returns 0 — and `waitForFunction(() => /^X/.test(body.innerText), ...)` requires body to START with X (false). Prefer a precise per-element selector (e.g. `.locator('.label-class')` or `.filter({ hasText: /^X/ })`) over body-wide anchored regexes.
- Canvas "Dashboard settings" button title is `"Dashboard settings (number format, theme, defaults)"` — must use `button[title*="Dashboard settings"]` (contains), not exact match.
- Intl compact `compactDisplay:'short'` renders LOWERCASE `1.2k` / `3.4m` / `5.6b`, not K/M/B. That's the spec; don't fight it.

## Bold perception-bug — second fix: make the effect unmistakable

User pushed back: *"the bold thing doesnt work"*. My earlier probe (probe-chart4) proved the
Bold state DID propagate (font-weight 600→700, button active class flipped) — so I'd concluded
"it's a perception bug, the live Title preview fixes it". The user rejected that verdict. They're
the ground truth, so I re-investigated instead of defending.

### What the decisive probe actually showed
probe-bold.mjs (persistent browser context: register → upload `sample.csv` →
Canvas tab → add chart → set region/sales → open chart drawer → click Bold) measured every
`span.cursor-move` before/after:
```
BEFORE  4│'Sum of sales by region'│600│14px│false
AFTER   4│'Sum of sales by region'│700│14px│true   ← only chart-card title (KPI titles unchanged)
```
- Mechanically **Bold works**: weight flipped 600→700, `font-bold` class added.
- But 14px/600→14px/700 is a **single weight step on a tiny title** — visually imperceptible.
- The KPI cards (500/12px) and the chart title (600/14px) are siblings; the chart title looks
  barely different from a semibold KPI label at that size.

So my "Title preview" alone (also text-sm 500→700) was equally subtle — it didn't solve the
problem, just moved the imperceptibility into the drawer.

### The real fix: make Bold produce an OBVIOUS visual change
In `frontend/src/components/ChartTile.vue`:
1. **Canvas chart title span (line ~1095)** — when `config.bold` is true render
   `text-base font-bold text-ink-gray-9` (16px/700/dark); otherwise `text-sm font-semibold
   text-ink-gray-8` (14px/600/lighter). That's a **size jump (14→16px) + weight (600→700)
   + colour (gray-8 → gray-9)** — three reinforcing deltas.
2. **Drawer Title preview (~line 1113)** — same conditional: bold = `text-base font-bold
   text-ink-gray-9`, default = `text-sm font-medium text-ink-gray-8`. Now the preview in
   the pane jumps visibly when the toggle flips, so the user sees the effect *while they're
   looking at the control*.
3. **Inline-edit title input (~line 1088)** — same conditional class appended so editing
   the title while Bold is on shows the bigger/bolder input.

### Verification (probe-bold.mjs, screenshots-bold/)
- AFTER weight `700`, size `16px`, `bold:true` (was 600/14px/false). KPI tiles unchanged.
- `screenshots-bold/canvas-before.png` shows "Sum of sales by region" modest (14px gray-8).
- `screenshots-bold/canvas-after.png` shows the same title clearly larger, heavier, darker

- `screenshots-bold/drawer-before.png` shows "TITLE PREVIEW" with the title in medium

### Lessons (worth keeping)
- A toggle that "works mechanically but is imperceptible" is indistinguishable from a broken
  toggle. Test with `getComputedStyle` AND a visual diff (before/after screenshots). When a
  weight-only change at a small size is the whole effect, treat it as a bug.
- A live in-pane preview is necessary but not sufficient — the preview itself must be loud
  enough to *read* as a change. Subtle previews don't sell the fix.
- The probe's first attempt clicked the FIRST `.group.cursor-pointer` — which on this canvas
  is a KPI card whose drawer has no Bold button. Selector matters: chart card root has class
  `group` (and `tile-drag-handle`), not `.group.cursor-pointer`. Use `.group` filtered by the
  chart's title text to land on the chart tile, not a KPI tile. Charts render to SVG, not
  canvas — so `:has(canvas)` doesn't work as a chart-vs-KPI discriminator.
